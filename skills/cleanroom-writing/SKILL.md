# Cleanroom Writing

Use this skill to produce a final artifact from a conversation or workspace that contains superseded decisions, rejected alternatives, internal rationale, or exploratory discussion.

Follow the user's requested language for the deliverable. If unspecified, preserve the language of an existing source document; for a new document, use the language of the user's request. The language of these instructions does not determine the output language.

## Separate discussion from deliverable state

Before drafting, determine whether the user wants exploration or a final artifact. Apply the clean-room workflow only to the final artifact. Discussion may contain alternatives and reasons; the artifact may contain them only when they serve its intended reader and the user has retained them.

Build an authoritative state from the latest explicit decisions and source materials:

- **Approved content:** facts, claims, wording, structure, and requirements allowed in the artifact.
- **Approved changes:** concrete edits that must be applied.
- **Excluded history:** rejected options, superseded wording, abandoned assumptions, and reasons that are useful only for making decisions.
- **Unresolved matters:** questions that must remain open or require user input. Do not silently choose among materially different outcomes.

Later explicit decisions override earlier ones. Treat rejected or superseded material as audit data, not drafting material.

## Draft from a clean brief

Create a clean internal brief containing only approved content, approved changes, applicable source material, and necessary audience or format constraints. Draft from that brief rather than narrating the full discussion.

Prefer direct, positive statements of the final position. Do not mention an abandoned alternative merely to say that the artifact does not use it. Do not include modification history, internal rationale, reviewer-facing defenses, or phrases that address an invisible prior draft unless the intended reader needs them.

When the user says not to mention a concept, record the concept only in the excluded-history audit set. Do not echo it into the artifact through constructions such as “not X but Y,” “no longer X,” or “unlike X.”

## Audit before delivery

Perform a separate clean-room audit after drafting:

1. **Traceability:** Every substantive statement must come from approved content, the authoritative source, or a necessary inference that is clearly within scope.
2. **Supersession:** Remove wording or assumptions overridden by later decisions.
3. **Decision-history leakage:** Inspect contrastive and temporal phrases such as “not…but,” “no longer,” “unlike,” “previously,” “instead of,” “to avoid misunderstanding,” and references to an original or former version. Keep them only when they communicate necessary final content to the intended reader.
4. **Negative-instruction leakage:** Check whether excluded concepts reappear inside a denial, disclaimer, or explanatory aside. Remove them when the positive final statement stands on its own.
5. **Rationale leakage:** Remove reasons for choosing an approach when the deliverable needs only the chosen approach.
6. **Consistency:** Ensure repeated definitions, steps, examples, tables, figures, and summaries all reflect the same final state.

These phrases are warning signals, not forbidden words. Preserve genuine comparisons, limitations, exclusions, and safety qualifications when the task or audience requires them.

## Existing plans and artifacts

When a decision log or modification plan exists, keep internal rationale visibly separate from final wording. Before editing an artifact, extract a clean execution list containing only approved changes and final text. Apply the relevant document, presentation, spreadsheet, or code workflow for the actual artifact format, then run this skill’s audit on the finished content.

Do not place the authoritative-state ledger, excluded-history list, or this workflow description inside the final artifact unless the user explicitly asks for them.

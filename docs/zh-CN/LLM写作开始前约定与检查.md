# LLM写作开始前约定与检查

## 使用目的

本约定用于存在多轮讨论、多个备选方案、旧版本文稿或反复修改的写作任务。它的目标是让讨论过程服务于决策，但不让废案、内部理由和版本差异自动进入最终文稿。

可在工作开始前将“开始前约定”完整发送给LLM，并在每轮形成重要决定后更新“最终有效状态”。

## 开始前约定

```text
本任务将区分“讨论过程”和“最终文稿”。

讨论过程中可以提出、比较和否定不同方案，但讨论过的内容不因此自动成为最终文稿的素材。只有被明确确认的内容，才属于最终有效状态。

请将任务中的信息区分为以下四类：
1. 已确认内容：允许进入最终文稿的事实、主张、定义、措辞和结构。
2. 已确认修改：最终需要执行的具体变更。
3. 内部理由和排除内容：用于讨论或决策，但不得进入最终文稿的理由、废案、旧措辞和被覆盖的决定。
4. 未决事项：尚未确定的问题，不得自行选择会实质改变结果的方案。

后出现的明确决定覆盖此前决定。被否定或被覆盖的内容只用于检查，不得通过否定句、对比句、免责声明或补充说明重新写入最终文稿。

正式写作前，请先依据已经确认的决定形成一份纯净执行清单。该清单只包含最终有效内容和最终修改要求，不复述废案，也不解释为什么没有采用旧方案。

最终文稿应直接陈述最终状态。除非目标读者确实需要了解比较、历史或排除关系，否则不要使用“不是……而是……”“不再……”“不同于旧方案……”“为避免误解……”等面向讨论历史的表达。

在我明确要求生成或修改最终文稿之前，只讨论和记录决定，不提前改写成稿。
```

## 最终有效状态记录表

讨论过程中持续维护下表。内部理由可以保留在记录中，但必须注明“不写入成稿”。

```markdown
# 最终有效状态

## 已确认内容
- 

## 已确认修改
- 

## 内部理由 不写入成稿
- 

## 排除内容 不写入成稿
- 

## 未决事项
- 

## 成稿格式与受众要求
- 
```

## 正式写作前检查

在开始生成最终文稿前，逐项确认：

- [ ] 已确认内容和已确认修改均有明确记录。
- [ ] 每个重要问题只有一个当前有效结论。
- [ ] 新决定已经覆盖并标记旧决定。
- [ ] 废案、旧版本措辞和内部讨论理由已放入排除区。
- [ ] 未决事项没有被当作已确认内容。
- [ ] 已明确哪些内容只用于解释决策，不能写入成稿。
- [ ] 已明确目标读者是否需要看到比较、反驳或历史背景。
- [ ] 已从最终有效状态提取纯净执行清单。
- [ ] 纯净执行清单中没有复述废案或旧版本。

## 交付前检查

- [ ] 每个实质性陈述均能追溯到已确认内容或指定源材料。
- [ ] 文稿没有出现已经被覆盖的定义、数字、结论或方案。
- [ ] 文稿没有为一个已经删除的方案继续辩解。
- [ ] 文稿没有把内部修改理由写成面向读者的正文。
- [ ] 否定句和对比句确有面向目标读者的必要性。
- [ ] 正文、标题、摘要、示例、表格和图示反映同一个最终状态。

## 简短调用版

在不方便发送完整约定时，可使用：

```text
请把讨论过程与最终文稿严格分开。只有明确确认的内容可以进入成稿；废案、旧版本、内部修改理由和被覆盖的决定只能用于检查，不能通过“不再”“不是……而是……”“不同于旧方案”等表达重新进入文稿。正式写作前先形成只包含最终有效内容的纯净执行清单，成稿后再检查是否存在决策历史泄漏。
```

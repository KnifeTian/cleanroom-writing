# LLM文稿废案回流检查与修复

## 使用目的

本检查用于写作开始前没有建立有效状态边界，或者文稿已经出现废案、旧版本、内部理由和讨论痕迹回流的情况。

检查目标不是简单删除所有否定句，而是识别哪些内容只是在回应已经不存在的讨论背景，并把文稿恢复为面向目标读者的最终状态。

## 检查指令

可将以下内容与待检查文稿、讨论记录或修改计划一并发送给LLM：

```text
请对这份文稿进行“废案回流检查”，暂时不要直接修改文稿。

首先根据讨论记录、修改计划和最新明确决定，区分：
1. 当前有效内容；
2. 已被覆盖或否定的内容；
3. 仅用于内部决策的修改理由；
4. 尚未解决的问题。

然后逐处检查现有文稿，列出可能的回流内容。每一处都要说明：
- 原文位置和原句；
- 它对应哪个旧方案、内部理由或已经结束的问题；
- 目标读者是否确实需要知道这些信息；
- 建议保留、删除还是改为正面表述；
- 如果需要修改，给出不携带讨论历史的建议写法。

在我逐条确认之前，不要直接修改文稿。全部问题确认后，先生成一份纯净修复清单，再统一修改。

不要把所有“不”“没有”“无需”等词机械认定为错误。涉及真实限制、必要排除、安全条件、法律边界或目标读者需要的比较时，应当保留。判断标准是该内容是否服务于最终文稿，而不是它是否采用否定形式。
```

## 第一阶段 建立当前有效状态

如果此前没有决策记录，先从材料中恢复一份临时状态表：

| 内容 | 当前状态 | 依据 | 是否允许进入成稿 |
|---|---|---|---|
| 方案、定义或措辞 | 已确认、已否定、已覆盖、未决 | 用户最后决定或权威源材料 | 是、否、待定 |

判定规则：

1. 用户后续的明确决定优先于较早决定。
2. “讨论过”不等于“确认采用”。
3. 没有结论的问题保持未决，不能由LLM自行补成最终结论。
4. 修改理由默认属于内部材料，除非目标读者需要了解。
5. 无法判断状态时，先提出问题，不要通过猜测完成清理。

## 第二阶段 定位回流信号

### 一 版本历史信号

- 不再……
- 此前……
- 原方案、旧方案、原文、修改后……
- 与之前不同……
- 现改为……

检查这些句子是否只是在描述版本变化，而不是最终技术、事实或结论。

### 二 废案否定信号

- 不是……而是……
- 并非采用……
- 不考虑……
- 不要求……
- 不涉及……
- 无需……

检查被否定的概念是否原本已经可以完全不出现。

### 三 内部辩解信号

- 为避免误解……
- 需要说明的是……
- 应当指出……
- 这里特别强调……
- 虽然存在……但是……

这些表达未必错误，但常用于回应讨论参与者，而不是服务最终读者。

### 四 决策理由信号

- 由于我们此前……
- 考虑到原方案……
- 为解决审阅意见……
- 因此删除或保留……

检查它们是否属于修改记录而非正文内容。

### 五 隐性概念回流

即使没有明显的否定词，也要检查：

- 已删除方案的术语是否仍出现在标题、摘要、示例或图示中；
- 旧版本的变量、数字、定义和步骤是否残留；
- 新方案是否仍在回答旧方案才会产生的问题；
- 表格、流程图和总结是否仍保留旧结构。

## 第三阶段 逐条分类

对每个疑似问题使用以下格式：

```markdown
## 问题编号

- 位置：
- 当前原文：
- 涉及的历史内容：
- 对目标读者是否必要：是、否、待确认
- 建议：保留、删除、正面改写、待确认
- 建议写法：
- 内部理由 不写入成稿：
- 状态：待讨论、已确定
```

## 第四阶段 形成纯净修复清单

全部问题讨论完成后，从逐条记录中重新提取执行清单。执行清单只包含最终操作，不复述废案及其详细理由。

```markdown
# 纯净修复清单

## 删除
- 位置：
  删除内容：

## 替换
- 位置：
  最终文字：

## 新增
- 位置：
  最终文字：

## 保持不变
- 位置及内容：

## 同步修改
- 标题、摘要、正文、示例、表格、图示和附件中的对应位置：
```

## 第五阶段 修复后复核

- [ ] 已删除的概念没有以否定句重新出现。
- [ ] 内部修改理由没有进入成稿。
- [ ] 新文稿不再与看不见的旧版本对话。
- [ ] 必要的限制、排除和风险说明没有被误删。
- [ ] 每处修改都来自逐条确认结果。
- [ ] 同类内容已经在全文和图示中同步处理。
- [ ] 文稿可以被不了解讨论历史的读者独立理解。

## 简短调用版

```text
请先检查这份文稿是否存在废案回流或决策历史泄漏，不要直接修改。逐处列出原句，判断它是否来自被否定方案、旧版本或内部修改理由，并说明目标读者是否需要它。建议分为保留、删除、正面改写或待确认。全部逐条确认后，再生成只包含最终操作的纯净修复清单并统一修改。
```
